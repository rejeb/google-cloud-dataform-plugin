Google Cloud Dataform for IntelliJ IDEA: full language support for your projects, letting you write, navigate, run and debug SQLX pipelines without leaving the IDE.

Read the documentation and the feature guides.

SQLX Language Support

  • Full syntax highlighting for SQLX files, covering embedded SQL, JavaScript and config blocks.
  • Smart code completion for built-in Dataform functions (ref(), declare(), publish(), etc.), JavaScript/TypeScript symbols, and Dataform template expressions (${...}), with automatic completion popup on $.
  • Native BigQuery SQL dialect support, including syntax validation and real-time error highlighting.
  • JSON Schema-powered validation and autocompletion for workflow_settings.yaml, generated dynamically from your project's Dataform configuration.

Config Block Assistance

  • Property completion in config { } blocks, scoped to the declared action type and generated from the @dataform/core version installed in the project; inserts a value skeleton matching the property type, or moves the caret to the existing value.
  • Value completion for enumerated properties, tags already used in the project, and the action's own columns in columns, clusterBy, uniqueKey and assertions.
  • partitionBy completion with the BigQuery partitioning expressions matching the column types, plus an inspection and quick fix for partitionBy written as an object.
  • Validation of unknown config keys and invalid enumerated values, including legacy shorthand forms (uniqueKey: "id", dependency targets as objects).
  • Quick Documentation (Ctrl+Q) on config keys, describing what each key expects.

Template Expression Evaluation

  • ${...} expressions and workflow settings references are folded to their evaluated value, computed with the project Node.js interpreter; click the value to show the source again.
  • Quick Documentation on an expression shows its evaluated value.

Compilation & Diagnostics

  • Background project compilation on save and while editing.
  • Dataform compilation errors and BigQuery dry-run errors placed on the exact tokens of the SQLX file, with inline error chips.
  • Editor banner listing the errors that cannot be placed in the file.
  • Build tool window listing the compilation errors, with their code frame, and the failing BigQuery dry runs, grouped per file.

SQLX Preview Editor

  • Split editor next to each SQLX file with the action's lineage graph, compiled query and resolved table schema.
  • One block per action, with its assertions in their own tabs, resizable SQL blocks and a Copy button.
  • Test preview for unit test files.

BigQuery Cost

  • Bytes and estimated on-demand cost of each query in the compiled preview, with a total for the file.
  • Scripts, which BigQuery cannot estimate, show Run to estimate: Run Query measures their bytes and cost.
  • Bytes billed and cost of executed queries and workflow runs, per action and per run.
  • Prices from Google Cloud Billing for each query location or a fixed price per TiB; capacity projects show bytes only.

Navigation & Code Intelligence

  • Jump between references, includes and declarations with Ctrl+Click / Ctrl+B.
  • Column window: Ctrl+Click a column in a SQLX query to see where it is declared and every place that reads it across the project, and jump to any of them.
  • Show Column Usages (Alt+Shift+U, also available from the editor context menu) opens the same window.
  • Quick Documentation (Ctrl+Q) for table references, resolved schemas, column metadata, and the built-in BigQuery function catalog (signatures, descriptions, examples).
  • Clickable links to workflow configuration properties.
  • Find Usages on the fields of STRUCT columns.

Refactoring

  • In-place column rename (Shift+F6) with its own dedicated engine: it walks the plugin's column lineage graph to propagate the new name across every file where the column flows, through CTEs, subqueries and SELECT *, with the config keys and unit tests that name it, then refreshes the resolved schema.
  • Impact analysis on save: when a saved change renames, removes or retypes a column read downstream, the affected actions and their BigQuery errors are listed per file in the Build tool window.
  • Rename downstream usages: after renaming a column in its action, a quick fix renames every downstream read of the old name through the rename preview.

Data Lineage

  • Built-in lineage graph view (Open Dataform Lineage action) that visualizes upstream/downstream dependencies between Dataform actions, each drawn as a card listing its columns and their types.
  • Column-level lineage tracing, so you can trace exactly where a given column's data originates across your pipeline, including through renamed/aliased columns, and search the lineage by column name.
  • Knowledge Catalog lineage: switch the graph to the lineage BigQuery recorded when the jobs ran, for the whole repository and cached in the IDE, with tables outside the repository, when each table was last written, the runs behind each link, a trace up to 5 levels, and the differences between what the code declares and what ran.

Run & Execute

  • Native run configurations for Dataform workflows, launched straight from IntelliJ's Run/Debug toolbar.
  • Gutter icons in the SQLX editor to run the current action, or the actions sharing one of its tags; the first run from a file opens a dialog to review its options.
  • Run console with a status header, the action tree with durations and a Show Failed Only filter, and per action a Summary, the Executed SQL and a timeline of its BigQuery jobs and statements, with the failing line marked.
  • Links from the invocation and each job to the Google Cloud console.

Unit Tests

  • Create Dataform Test from the Project view or editor context menu of a table or view: generates definitions/tests/<path>/test_<action>.sqlx, where <path> is the file's directory under definitions, with one input per dependency and the expected output, pre-filled from the resolved schemas.
  • Column completion after AS in input blocks and in the expected output, including the fields of STRUCT and arrays of structs.
  • Generate SELECT from schema intention (Alt+Enter) filling an input or the expected output with a typed placeholder row.
  • Completion and navigation for the tested dataset and the input names of a test.
  • Run tests from the gutter or a dedicated run configuration; results appear in the IDE test runner, with an expected/actual diff for failing tests.

Google Cloud Integration

  • Dataform Tools tool window: manage repositories, browse and create workspaces, and push or pull files between the local project and a GCP Dataform workspace.
  • Files tab with the status of the workspace files, and a Changes tab to commit and push the workspace.
  • Fetch to Local, Compare with Local and Open in Google Cloud Console on workspace files.
  • Compare File with Remote to diff a local file with its version in the workspace.
  • BigQuery query execution in the Services view, with paged results in a data grid, the job details and their cost.
  • Google Cloud authentication status and sign-in prompts in the editor.

Signing in to Google Cloud is optional. See the Privacy Policy for how the plugin handles your data.

Formatting

  • Built-in formatter aware of injected SQL, JavaScript and config blocks inside SQLX files.
  • Optional integration with SQLFluff for external, configurable SQL formatting.

Project Tooling

  • New Project wizard to scaffold Dataform projects with the correct structure.
  • New SQLX File action with ready-made templates for every Dataform action type: Table, View, Incremental table, Assertion, Operations, Declaration, and Unit test.
  • Dataform CLI and Core detection, with one-click installation from the plugin settings.
  • Suggests moving dataformCoreVersion from workflow_settings.yaml to the @dataform/core dependency of package.json.
  • Disabled actions (disabled: true) are greyed out in the Project view.
  • Fast project indexing of Dataform core definitions and JavaScript symbols for responsive completion and search.
